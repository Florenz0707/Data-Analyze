# M6 缓存性能基线报告

> 采集日期：2026-09-02（Asia/Shanghai）
>
> 状态：缓存层基准完成；真实 HTTP/模型、多进程和长期驱逐指标仍待验收。

## 1. 评测范围

本次评测针对 M6 新增的共享缓存链路，覆盖最终答案缓存、检索缓存、冷路径写入和同 Key 请求合并。评测使用本机 Redis 6379，生产 Django 配置实际加载 `RedisCache`；模型生成和检索器使用确定性替身，不调用外部模型、不写入业务数据库。

完整机器可读证据见 [`evaluation/m6/evidence/cache_performance_baseline.json`](../evaluation/m6/evidence/cache_performance_baseline.json)，可复现实验入口为 [`evaluation/m6/benchmark_cache_performance.py`](../evaluation/m6/benchmark_cache_performance.py)。

## 2. 条件与口径

| 项目            | 条件                                             |
| --------------- | ------------------------------------------------ |
| 操作系统        | WSL2 Linux 6.6.87.2，x86_64                      |
| Python          | 3.13.11                                          |
| Redis           | 127.0.0.1:6379，Redis 7.0.15                     |
| Django 缓存后端 | `django.core.cache.backends.redis.RedisCache`    |
| 缓存对象上限    | 262,144 bytes                                    |
| 回复命中采样    | 200 次；同一用户、会话、问题和回复               |
| 回复冷路径      | 50 个唯一 Key，计算并写入                        |
| 检索命中采样    | 200 次；同一查询、索引版本和参数                 |
| 检索冷路径      | 50 个唯一查询，替身检索并写入                    |
| 同 Key 合并     | 10 轮，每轮 16 个并发线程，替身生产者固定约 50ms |
| 结果统计        | P50、P95、P99、最大值；延迟单位为毫秒            |
| 评测持续时间    | 2.38s（不含进程启动开销）                        |

Redis 内存和驱逐数是实例级指标。评测只使用带随机命名空间的临时 Key，结束时删除本轮 Key；独立进程退出后的 Redis 状态为 `connected_clients=1`、`used_memory=1.04M`、`evicted_keys=0`。

## 3. 实测结果

| 场景                    |  次数 |     P50 |     P95 |     P99 |  最大值 | 结论                                     |
| ----------------------- | ----: | ------: | ------: | ------: | ------: | ---------------------------------------- |
| 最终答案 Redis 命中     |   200 |  3.89ms |  4.42ms |  5.02ms |  6.16ms | 低于 M6 ≤300ms 目标                      |
| 最终答案冷路径计算+写入 |    50 |  8.10ms |  8.95ms | 12.64ms | 12.64ms | 替身生产者，不代表真实模型耗时           |
| 检索 Redis 命中         |   200 |  0.35ms |  0.50ms |  0.55ms |  0.68ms | 命中键读取正常                           |
| 检索冷路径执行+写入     |    50 |  1.52ms |  1.78ms |  1.87ms |  1.87ms | 替身检索器，不代表 Chroma/Embedding 耗时 |
| 同 Key 16 并发总耗时    | 10 轮 | 80.20ms | 88.15ms | 88.15ms | 88.15ms | 10/10 轮均仅 1 个生产者                  |

缓存身份隔离检查通过：相同查询使用不同 metadata filter 时生成不同 Key；检索替身实际调用 51 次，正好对应 50 次冷路径和 1 次热 Key 首次填充，200 次热命中未重复调用检索器。

## 4. 与已有基线的关系

M0 记录的“同问题缓存命中”为单次 19.82ms，使用当时的本地缓存/完整 API 环境，且不是 P95，因此不能与本报告的 Redis 缓存层 P95 直接作严格同比。当前可确认的是：Redis 回复缓存层 P95 为 4.42ms，满足 M6 缓存命中接口 ≤300ms 的缓存层预算；完整 HTTP 请求仍需在后端服务启动、认证、数据库访问和真实模型条件下单独测量。

## 5. Redis 与计数器证据

本次进程内缓存计数器如下：

| 计数器                   |            值 |
| ------------------------ | ------------: |
| 回复命中 / 未命中 / 写入 | 200 / 50 / 51 |
| 检索命中 / 未命中 / 写入 | 200 / 51 / 51 |
| 同 Key 进程内等待数      |           150 |
| 缓存错误                 |             0 |
| 超大对象跳过             |             0 |
| Redis 原子锁等待         |             0 |
| 评测结束时 Redis 驱逐数  |             0 |

总命中率按答案和检索两类命中/未命中计数为 `0.7984`。该数值混合了冷路径和热路径，不能当作生产命中率；生产应按真实流量和时间窗口持续采集。

## 6. 验收结论与限制

已完成：

- 真实 Redis 后端上的答案缓存命中 P95、检索缓存命中 P95 和冷路径写入基线；
- 16 并发同 Key 请求在 10 轮中均只执行一次生产者；
- 缓存对象限制、缓存键过滤维度隔离和 Redis 驱逐计数均得到可复核证据。

尚未完成：

- 真实 HTTP `/api/llm/chat` 命中请求 P95；当前 8081 后端和 8082 前端未运行，无法安全声称全链路指标；
- 多进程/多 worker 同 Key 竞争和真实外部 Provider 首事件 P95；
- 24 小时以上 Redis 内存、命中率和驱逐趋势；
- 20 并发下的全链路错误率、串台和取消生效 P95。

## 7. 复现命令

在 Redis 6379 已启动的前提下，从仓库根目录运行：

```bash
DJANGO_TESTING=false REDIS_URL=redis://127.0.0.1:6379/0 \
  uv run --project backend/django_backend --frozen \
  python evaluation/m6/benchmark_cache_performance.py \
  --iterations 200 --single-flight-rounds 10 --concurrency 16
```

固定评测集数据校验和工具回归也已通过：`50` 条数据、`10` 条负样本、`3/3` 评测工具边界测试；检索质量复测保持 Recall@1 `0.8000`、Recall@5 `0.9500`、Recall@10 `0.9500`，两次运行 spread 均为 `0`，证据见 [`evaluation/m0/evidence/retrieval_baseline.json`](../evaluation/m0/evidence/retrieval_baseline.json)。
